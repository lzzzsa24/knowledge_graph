# 前端一致性规划（2026-11-22）

交接箱任务 #85，由 Claude 负责，范围为 `web/static` 与前端测试。所有问题都已在 8612 开发服务上核对过两种架构模式。查看视口为 1440×900。

## 一、现状问题

### 1. 两种架构模式的页面不一致

侧栏可以在“自制 Demo”和“RAG-Anything”之间切换。导航相同，但同名页面的结构差别很大。

| 页面 | 自制 Demo | RAG-Anything |
|---|---|---|
| 文献库 | 双维度交叉表 + 分层文献列表 | 纯文献列表，没有分类维度 |
| 知识记录（标签页） | 记录卡片，标题仍写“文献库” | 标题为“实体与关系”：232 个实体标签平铺，下面列出 838 条关系 |
| 文献入库 | 页标题“批量入库”，上传表单 + 批次进度 | 页标题“文献入库”，入库队列面板 |
| 项目概况 | 汇报页，含技术栈、流程和资料规模，页标题“混合键合知识图谱” | 入库队列面板（与文献入库页重复）+ 已发布索引，页标题“项目概况” |
| 全文检索 | 副标题在两种模式下完全相同，看不出检索的是哪个库 | 同左 |

命名也不统一：
- 导航写“文献入库”，Demo 页面标题写“批量入库”。
- 浏览器标签显示“知识记录”，页面标题却是“文献库”或“实体与关系”。
- 品牌副标题和网页标题仍是“知识图谱”。

### 2. 视觉规范不一致

| 项目 | 现状 |
|---|---|
| 字号 | CSS 中有 28 种，从 10px 到 32px，含大量 .5px。入库页大量使用 9–11px 小字 |
| 区块标题 | 13、15、16、17、21px 五种，字重 600、650、700 混用 |
| 圆角 | 3–22px 之间 10 余种 |
| 按钮 | 高度 26–45px，约 12 种；按钮类名 10 余种 |
| 页面宽度 | 920、1120、1160、1180 四种 |
| 颜色 | 除 49 个设计变量外，另有 51 个写死的颜色值。暗色模式只覆盖了部分变量 |
| 内联样式 | Demo 知识记录页渲染出 2,940 处，文献库 45 处；app.js 中有 17 处模板 |

### 3. 代码结构

- `app.js` 有 1,835 行，所有页面都写在这一个文件里，包括 RAG-Anything 视图。
- `styles.css` 中，批量入库的样式排在基础样式之前，RAG-Anything 的样式散落在各处。
- 侧栏架构切换同时存在按钮组和隐藏的下拉框两套控件。
- 各脚本缓存版本号的写法不统一。

## 二、规划

### 第 0 步：设计规范（统一变量）

| 项目 | 规范 |
|---|---|
| 字号 | 12 / 13 / 14 / 16 / 20 / 24 / 32（展示数字），不再使用 .5px |
| 标题层级 | 页面标题 24/700；区块标题 16/650；小节 13/600 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 |
| 圆角 | 6（小件）/ 10（控件）/ 14（卡片）/ 胶囊 |
| 按钮 | 28 / 34 / 40 三档高度；主要、次要、幽灵三种样式 |
| 颜色 | 全部走变量，补齐暗色模式；状态色（成功、警告、错误、进行中）单独成组 |
| 页面宽度 | 阅读型 920（问答、创新点），工作型 1180（其余页面） |

### 第 1 步：共用组件

页头（标题、副标题、架构标记、操作按钮）、区块卡片、按钮、标签、表格、统计数字、提示条，以及空状态、加载、错误三种状态。每个页面只组合这些组件，不再各写一套。

### 第 2 步：统一两种架构模式

- 同名页面采用同一套骨架，只是数据来源不同。页头统一显示当前架构。
- 某个架构不具备的能力，统一用“该架构暂不提供”的空状态说明，不再换成另一种布局。
- 统一命名：文献入库、知识记录、项目概况三处各只用一个名字；“知识图谱”字样改为与现状相符的名称。
- RAG-Anything 模式下的项目概况不再重复入库队列，改为与 Demo 相同的汇报结构，数据取自已发布索引。
- 如需补充分类维度等接口，再向 Codex 提出需求，接口就绪前前端降级显示。

### 第 3 步：逐页改造（每批改完都核对后再进行下一批）

1. 文献库与知识记录
2. 文献入库
3. 项目概况
4. 论文问答与创新点生成
5. 全文检索与阅读抽屉

### 第 4 步：清理与验证

- 内联样式改为类名；把 RAG-Anything 视图从 `app.js` 拆分为独立文件；整理 CSS 分区。
- 每批改完后执行以下验证：
  - 在 8612 上分别检查两种架构、亮色与暗色、窄屏三种情况；
  - 同步更新 `tests/*_ui.cjs`。
- 改动前将 `web/static` 备份到 `tmp/static_backup_20261122/`。

## 三、待用户决定

1. **两种架构的地位**。建议：RAG-Anything 设为默认和主线，Demo 标注为“旧版 / 对照”保留切换。另一种做法是两者长期并列。
2. **视觉方向**。建议：保留现有靛蓝色调，只收紧规范。另一种做法是改用汇报幻灯片的紫色系。
3. **动效**。建议：保留导航指示和必要过渡，去掉列表逐项入场动画。
