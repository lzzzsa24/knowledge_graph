## 2. 语料如何确定

三个采集分支独立查找公开期刊、会议及机构全文。共获取 31 篇论文和 1 份会议演示材料；正式试点采用 26 篇，另保留 5 篇背景论文，不把演示材料或仅有元数据的受限条目计入论文数。正式目录与排除记录分别保存于 [papers.json](../catalog/papers.json) 和 [excluded.json](../catalog/excluded.json)。这不是系统性综述，也未证明检索穷尽。

覆盖 Cu/SiO2、Cu/SiCN、表面准备与活化、Cu 下凹和形貌、接触键合、后退火、电学性能、界面强度和可靠性。保留少量有明确关联的组件级与扩展材料研究，并显式标记范围：

- `imec_02` 是 SiCN 介质 D2W 工艺演示，不作为完整 Cu 电连接验证。
- `imec_05` 是 SiO2 键合强度测量方法，不作为 Cu 接头强度数据。
- 聚合物混合键合标记为扩展范围；两篇综述只提供背景，不能作为新的独立实验样本。
- `journals_nano15201600` 的 Cu/MoS2/Cu 导电细丝与 SiCN 混合键合属于特殊界面，不能套用普通 Cu-Cu 接头的机理假设。
- 仿真论文的数值与实验值分开保存；预印本保留其文献状态。

题名与 DOI 已对照全文；关键数值、疑难表格及部分首页做了实际图像检查。没有宣称 265 页全部逐页视觉审阅。来源链接及许可信息以各采集清单保存内容为准；公开可下载不自动代表任意再分发权。

## 3. 知识记录与证据链

每条记录绑定文献、样品、材料体系、工序、物理量、原始数值/单位、条件和证据。证据保留原文、PDF 物理页、段落 ID 与位置，多个页面分别提供工艺条件和测量结果时保留多条出处。

工序包含表面准备 19 条、接触键合 8 条、后退火 19 条、测量 54 条、可靠性试验 7 条、材料表征 17 条、背景 4 条。记录类型为作者报告实验 108 条、作者报告仿真 11 条、作者解释 5 条、综述归纳 4 条。

独立复核的 19 处修正包括恢复原引文的 Unicode 字符，以及补全会改变解释的条件：把无空洞观察绑定到具体 chip 1；把尺寸保留为 pad size 而不猜成直径；明确 250/400 °C 属于后退火；保留高温/高电场下机理模型的适用限制。引文校验只允许空白差异，不通过改写数字或单位使其“匹配”。审计轨迹见 [校验明细](claim_validation_audit.json)。

Pint 仅对单个明确数字和可识别单位做换算，本轮 32/128 条满足该条件。范围、复合条件、多个数值和歧义保持原文，不能把未换算理解为数据丢失。图中实际连接文献、样品、知识记录和支持证据；工序及条件主要保存为结构化字段，尚未构成复杂工艺因果推理系统。

这些记录由 agent 抽取及交叉复核，没有专家金标准。原文引文通过只能证明可定位和字符一致，不能单独证明语义、实验设计或科学结论正确。128 条也不代表论文中所有知识已经抽完。

## 4. 解析器实测与选择

原生 PyMuPDF 完成 26 篇正文解析及表格候选抽取，记录耗时合计约 35.77 秒。`reliability_small_die_2022` 的字体映射形成乱码，却没有替换字符，因此“零乱码字符计数”不足以通过质量检查。针对该篇使用 Docling/RapidOCR 恢复 7 页正文，显式标注 OCR 来源并保留原生输出。

表格诊断选择 3 篇 MDPI 论文的 4 张表，设 52 个目标数值单元格，原页判读基准由 agent 建立。包含均值±误差的格子要求两者同时正确，完整通过还要求行列、单位、倍率与来源对应。

| 解析配置 | 完整通过的表 | 目标数值格结果 |
|---|---:|---|
| PyMuPDF find_tables | 0/4 | 17/52 可直接正确解释，主要问题为小数点脱离 |
| Docling 原生模式 | 1/4 | 有效结构中 9/9；其余 43 格因结构失效未评分 |
| Docling 强制 OCR | 1/4 | 有效结构中 9/9；其余 43 格因结构失效未评分 |
| MinerU pipeline/txt | 4/4 | 52/52，表格标签和数值关联通过 |

因此采用分工：PyMuPDF 提供正文和物理页证据；MinerU 优先处理定量表格；Docling/RapidOCR 用于乱码正文恢复。MinerU 正文仍出现串入内容及 SiO2 下标丢失，故不替换全部正文。Docling 表格曾出现 Ω→W、行合并与页眉串入；双渲染后端显示原表正常，但尚不能确定 Docling 内部根因。

另发现论文自身表值 131.02±3.41 GPa 与正文 131.2 GPa 不一致，保存差异，不将它归罪于解析器或擅自取平均。完整对照与原始输出见 [解析评估](parser_assessment.md)。该诊断样本有目的地包含难例，不能外推为各工具在所有论文上的准确率；公式、扫描件和其他出版商尚需验证。

## 5. 检索结果

BGE-M3 在本机 CPU 上编码 1,979 个分段用时 858.423 秒，约 14.3 分钟，不包含首次模型下载。向量输入取有效证据中规范化后不少于 80 字符的段落，短段仍保留在正文与关键词索引；原计时 JSON 的 `native_text_blocks` 名称未区分 OCR，但实际输入包含 OCR 路由后的有效证据。其间包含 2 个同 ID、同文本、同向量的 OCR 重复分段，Qdrant 建库时去重为 1,977 点。最终分段与当前有效证据可复核对应，最长 483 token，未超过设置的 512-token 上限。模型仓库 revision 已锁定于 [model_config.json](../model_config.json)。本轮未测 GPU 推理。

题库在查看检索结果前冻结，未根据结果调参；但题目和参考页仍由参与项目的 agent 设计，不是独立专家测试集。16 题中仅 12 个有参考证据的正例纳入以下命中统计。每路候选截取后按物理页去重，报告前 5 页中是否命中至少一个指定参考页，以及参考页的逐题平均召回率。

| 查询 | 方法 | 命中至少一个参考页 | 参考页平均召回率 |
|---|---|---:|---:|
| 预先给定英文检索句 | BM25 | 10/12（83.3%） | 70.8% |
| 预先给定英文检索句 | BGE-M3 语义 | 11/12（91.7%） | 76.4% |
| 预先给定英文检索句 | BM25 + 语义融合 | 10/12（83.3%） | 75.0% |
| 预先给定英文检索句 | 加入知识记录图谱证据 | 11/12（91.7%） | 77.8% |
| 原始中文问题 | BM25 | 0/12 | 0% |
| 原始中文问题 | BGE-M3 语义 | 9/12（75.0%） | 61.1% |
| 原始中文问题 | BM25 + 语义融合 | 8/12（66.7%） | 52.8% |
| 原始中文问题 | 加入知识记录图谱证据 | 8/12（66.7%） | 52.8% |

中文 BM25 没有中文分词和查询改写，语料主体为英文；其失败是当前配置的限制。英文结果不能宣称系统已自动把中文翻译成同样效果的检索句。图谱方法在本轮是知识记录关键词查找与支持证据边遍历，不是通用多跳推理；检索函数另支持工序/材料过滤，但本次评测没有启用过滤参数。

结果不足以证明图谱融合优于纯语义：英文两者命中相同，中文融合反而下降。当前中文入口应使用语义检索，英文术语可用关键词；先保留单路基线，再用未见题评估查询改写、重排和融合。4 道证据不足题保留在 [题库](../evaluation/retrieval_questions.json)，本轮没有评估其生成拒答率，也没有对 16 题测生成答案准确率。检索命中不等于答案正确。

详见 [英文摘要](retrieval_summary.json)、[中文摘要](retrieval_summary_zh.json) 和 `pilot/evaluation/` 的逐题结果。冻结题库 SHA-256：`893265dfab0856ebc14463b43261ba4632dce0d5c568fea766ed56d1f98695e0`。

## 6. LightRAG / RAG-Anything 的实际验证范围

对 3 篇论文的 18 条候选知识，执行了真实的 custom-KG 导入和 `RAGAnything.aquery(mode="mix")`：21 个节点、18 条关系、18 个文本块，实际使用本地 BGE-M3 生成嵌入。每条知识独立成节点，避免不同实验条件因相同两端实体而合并。

3 个保存的问答分别验证：区分 200 °C、1 h 键合与 200 °C、4 h 后退火；97% 对 95% 是约 2 个百分点且不能忽略两组退火温度不同；10 天导通观察不能外推为 150 °C 连续服役 10 年的统计寿命保证。结果包含知识 ID 和物理页出处。

模型回调由本会话 agent 通过文件桥接真实读取框架请求并返回回答，没有伪造固定模型存根；但没有配置、测试独立运行的模型 API。原始请求、实际检索上下文和回答全部保存在 [框架试验目录](../benchmarks/framework/session_bridge_01/report.json)。单题约 78–92 秒的墙钟时间包含 agent 等待和调度，不能作为 API 延迟基准。

本轮框架使用 JsonKV / NanoVectorDB / NetworkX 默认存储；项目独立建立的 Qdrant 本地索引不是 LightRAG 的 Qdrant 服务适配。框架没有导入全部 26 篇 PDF，也没有完成 RAG-Anything 多模态端到端验证。运行时快照尚标记待复核，之后 18 条均进入最终复核记录，事实值未改变；保留历史快照原样，避免把后续审核状态写回历史运行。

## 7. 根据结果确定的首版技术栈

| 层次 | 首版采用 | 选择依据与边界 |
|---|---|---|
| 开发与复现 | Python 3.12、锁定依赖、JSONL 原始/审计记录 | 本机已安装并实际运行；数据步骤可单独重建 |
| 正文与定位 | PyMuPDF | 26 篇批处理完成，保留物理页与 bbox；不作为唯一质量判断 |
| 定量表格 | MinerU 按页处理 + 原页核对 | 本轮 4 张诊断表表现较好；不全量接管正文 |
| 乱码恢复 | Docling + RapidOCR | 一篇乱码正文恢复成功；错误表格并非强制 OCR 就能解决 |
| 数据约束 | Pydantic + Pint | 结构、引文、样品/工序绑定、保守单位换算 |
| 事实与图谱 | SQLite + NetworkX / GraphML | 当前 128 条规模足够，简单可审计；暂不引入 Neo4j 等额外服务 |
| 向量模型与索引 | 本地 BGE-M3 + Qdrant local | 全语料分段编码及中英文检索已实测，模型 revision 固定 |
| 查询 | 中文先语义，英文保留关键词；融合保留实验配置 | 现有数据未显示融合稳定增益；重排器与自动查询改写尚未验证 |
| 展示 | Streamlit | 文献、条件、原引文及 PDF 页可直接检查，中文语义查询通过集成测试 |
| 生成与多模态框架 | LightRAG / RAG-Anything 保留为候选 | 文字路径跑通；独立模型服务、全语料导入和多模态需后续比较 |

这是已经运行的首版基线。最终长期栈仍需更多未见页面与问题验证，不能由 26 篇试点决定所有组件。没有进行 Neo4j、其他嵌入模型、重排器或 GPU 的性能对比，暂缓采用不表示它们效果差。

## 8. 后续收敛条件

下一阶段先扩大未参与调试的表格与问答测试，保持题库冻结和语料版本可追溯，再决定是否增加组件：

1. 补足不同出版商、扫描页、公式、跨页表和图中数据；将解析错误与论文自身矛盾分开登记。
2. 扩展到至少 60 个覆盖条件比较、否定证据和跨文献问题的题目，并由领域人员抽检关键数值与参考答案；agent 自评单独报告。
3. 对比纯语义、查询改写、重排、图谱融合；报告引用正确性、条件绑定、证据不足时的拒答和运行成本，而非只报检索命中。
4. 配置可独立运行的模型服务后，对同一冻结语料试跑 RAG-Anything 全链路，再决定是否把生成服务接入界面；保留当前可用的证据浏览与检索路径。

本轮交付完成的是语料获取、覆盖性知识试抽取、可追溯检索原型和实测选型依据；不包含实验结论的专家认证、生产部署或无人值守文献自动更新。
